# 权限与原生 Shell 隔离

权限判断只在领域层实现；应用层 PermissionService 统一决策编排、审批、参数重判、版本快照、授权提交和执行能力签发；基础设施仓储及系统沙箱在组合入口注入。界面只选择服务端提供的选项 ID。

## 会话授权状态与恢复

`Session.authorization` 持有领域模型 `SessionAuthorization`，统一管理类型化会话规则、权限模式、Agent/Plan/Ask 执行限制与父级授权关系。父级引用仅指向授权对象；规则以不可变快照提供。交互子 Agent 的会话批准归属根用户会话，父级撤销和硬限制实时生效。Project 与用户授权独立存储，由 `application/permission/PermissionService` 组合成完全不可变的有效快照；通过文件轻量修订、继承和边界变化使缓存立即失效，不复制进会话模型。

检查点仅支持版本 8，权限状态保存在嵌套 `authorization` 中。旧检查点明确报错，不迁移、不改写或删除文件。独立权限仓储仍使用版本 2。编解码及历史预览不读取权限仓储；开始执行前，应用服务重新加载当前授权并校验 cwd，仓储中的撤销结果优先于检查点快照。不存在、受保护或超出当前目录范围的 cwd 恢复到执行根；执行根本身不可用时拒绝恢复。

## 授权

一次批准仅授权当前调用的实际目标，不产生记忆。文件记忆默认精确到文件。目录授权必须明确选择，递归覆盖目录及子目录，并标明只读或可读写。会话授权在恢复同一会话后仍有效；长期默认保存到当前项目；所有项目长期授权放在高级选项。

审批卡推荐有实际复用价值的会话范围：项目内文件可选父目录、简单直接命令可选程序及参数范围、HTTP 可选同源与当前方法。更多选项保留精确文件、精确命令和精确 HTTP 路径。保存到项目或所有项目必须显式选择，不从会话批准自动升级；界面始终提交服务端选项 ID，不自行构造授权。

简单直接命令支持“程序，允许任意参数”，并显示实际绑定的程序路径、工作目录和期限。例如允许 Python 后，可以执行 `-c` 代码、任意脚本及其启动的子进程；这项授权不会逐条审批解释器内部启动的命令。部分有意义的命令还可选参数前缀，例如 Git 的只读子命令；后续参数仍不受该前缀规则限制，不将“只读子命令”的名称当作副作用证明。精确命令批准仍然可用。程序路径标识不是可执行文件内容的哈希保证，替换二进制或脚本属于程序信任边界。

程序候选来自可确认的直接调用，以及仅由 `&&`、`||`、`;`、`|` 串联的复合命令：其中每个程序都已授权才放行，`cd`、`echo` 等无副作用命令不单独要求授权，并可一次记住缺失的多个程序。命令替换、子 Shell、后台任务、heredoc 和写文件重定向仍走完整命令的一次或精确批准；`sh -c 'python …'`、`env python …` 也不冒充直接 Python 调用，仍可走完整命令的一次或精确批准。POSIX 的识别与实际启动使用一致的字面量参数；Windows PowerShell 不套用 POSIX 解析器。在 sandbox 模式中，程序授权保持离线，文件范围继续由原生沙箱限制，联网仍须本次单独批准。host 模式中，命令和它启动的子进程具有宿主账户的文件与网络访问权限。

HTTP 读取可选择“当前方法 + 同源所有路径”或“当前方法 + 精确路径”。同源明确包含协议、主机和端口，不自动覆盖子域或其他端口；精确路径不固定查询参数，界面明确写出“查询参数不限”。写方法保持一次批准。记住一个读取工具时，界面显示具名工具及允许的操作，不暗示覆盖所有工具或任意副作用。

界面保存的文件和目录授权按资源与操作匹配，不绑定某一个文件工具；例如记住一个文件的读写授权后，写入和编辑工具可以在同一个文件上复用授权，相邻文件仍需单独批准。显式配置的工具限制继续约束实际调用，权限页会标明该限制。策略投影显示真实的会话、项目和用户期限，以及覆盖默认策略的只读边界。

审批卡将命令或文件路径与内容预览分开显示，截断预览明确说明批准作用于完整内容。风险提示只描述已识别的删除、移动、Git 修改等特征，不代替领域层授权和系统隔离。保存或撤销遇到版本冲突时，界面展示最新状态并保留错误提示，由用户查看后重试；不自动扩大授权或重新提交。

Shell 审批先检查系统隔离状态，未就绪时按钮和快捷键都不能放行，拒绝仍可用。初始化完成后仍需明确批准当前调用。选中联网会把主按钮改为“允许此次联网”，同时禁用保存离线命令授权，避免记忆授权静默丢失联网选择。

Web 权限文案和审批测试数据由 `uv run python scripts/generate_permission_fixtures.py` 从后端生成；后端测试验证生成结果，浏览器测试使用相同的结构化数据覆盖中英文、窄屏、授权期限、初始化和联网交互。

项目空间位于用户运行状态目录 `projects/<现有项目身份>/permissions.json`，不读取仓库里的授权文件。worktree 共用项目授权；工作区规则相对当前执行根解析。外部资源使用基础设施解析出的绝对规范路径。主 Agent、交互子 Agent 共用用户会话授权；父会话的硬模式限制会约束子 Agent，模式变化使旧许可失效。会话授权独立存储在 `permissions-sessions/<session_id>.json`，checkpoint 只记录该会话授权快照。恢复时仓储里的撤销结果优先。

固定优先级：保护资源、模式硬限制和只读边界 → deny → ask → 明确授权 → 模式默认。bypass 只减少当前边界内的确认。HTTP 授权包含协议、主机、端口、方法及所选路径范围；HTTP 拒绝规则不影响 HTTPS。精确 Shell 命令记忆绑定工作目录及沙箱能力，限本会话；程序与参数范围可显式保存到会话、项目或用户期限，绑定程序路径和执行方式，不绑定工作目录或授权目录列表，文件范围仍由当前沙箱决定。副作用不明的工具调用只支持一次批准。

权限文件独立使用版本 2，不改变会话 checkpoint 版本。旧授权格式、additionalDirectories 和含糊规则直接报错，不迁移、不扩大授权。新记录携带稳定 ID、lifetime、project_id、资源、操作和来源。会话、项目、用户授权各自保存，不把长期记录复制成会话记录。

管理接口添加授权传入 resource、lifetime、expected_version；撤销传入稳定 ID、source、expected_version。旧版本更新返回 409 及最新状态。审批完成、保存之后及实际执行之前都检查版本；跨进程修改会被重新读取。撤销取消待审批请求，令待执行调用失效，并停止依赖该授权的后台 Shell；已完成副作用不回滚。

管理页按会话、项目、用户期限展示文件、目录、命令、程序、网络和具名工具规则，显示其真实范围并使用同一个撤销入口。撤销删除指定记录；若仍存在其他匹配规则，访问可能继续有效，不能把删除一条规则解释为对资源新增拒绝。命令文本规则只匹配 Wright 当前直接发起的调用，无法拦截已授权程序内部所有间接调用；sandbox 模式的文件和网络限制由执行沙箱落实；host 模式不提供这些系统隔离。

## 调用、网络与事务边界

Dispatcher 准备工具与调度执行，调用 `PermissionService.authorize` 得到 `AuthorizedInvocation`。文件引用共用这个入口，界面资源授权使用 `grant_resource`。纯领域 Resolver 解析资源、判断准入并描述许可事实；应用 `AuthorizationWorkflow` 使用注入的审批适配器，重新判断被改写的参数。工具提供审批详情描述器，应用投影生成现有审批卡和策略摘要。Ask/Plan 操作上限来自同一份领域定义。

内置 `http_request` 和 `web_search` 使用注入的受限网络接口。不可变许可绑定规范请求目标、查询参数、方法、语义操作及调用身份；发送前核验版本和目标。Web 搜索仍以 POST 执行 `network_read`，可记住具名工具的该操作；`knowledge_search` 同样可记住具名 `network_read`。不自动重试或跟随重定向，供应商凭据由基础设施获取，不进入授权规则或审批投影。Knowledge 写入和 MCP 仍按当前外部调用边界审批；本次不为 `persistent_write`、`execution_control` 或副作用未知的操作新增记忆选项。

专用权限工作单元将授权文件与显式登记的检查点参与者放入同一个事务。基础设施版本 1 日志记录参与文件前后内容与校验和，执行 `PREPARED → 原子替换 → COMMITTED → 清理`，同步文件及目录。未提交事务回滚，已提交事务完成新内容；恢复可重复执行，逐项收集补偿失败。恢复不完整时禁止签发许可。普通检查点保存、重命名、执行检查点读取和授权操作共享锁顺序与恢复协调，避免旧日志覆盖后来的合法写入。日志目录属于保护范围，恢复只写登记的权限或检查点文件。

## Shell 后端

`Session.execution_mode` 为 `sandbox`（默认）或 `host`，与工作区 `environment=local|worktree`、审批策略 `permission_mode` 独立。worktree 仅隔离工作目录，不是系统安全沙箱。首版执行方式仅属于会话，不支持项目或全局 host 默认；新会话和旧检查点缺少该字段时使用 sandbox，恢复已有 host 会话会保留该选择。

CLI 新会话可显式使用 `wright --execution-mode host` 或 `wright --execution-mode sandbox`，恢复命令保留原会话的方式。

在 Web 新建会话时通过“Shell 执行方式”选择，已有会话在检查器的权限页切换。创建 API 的请求体支持 `execution_mode`，切换使用 `POST /api/v1/sessions/{id}/policy` 的同名字段。会话摘要、快照、授权投影和审批请求返回实际执行方式。

切换必须在根会话的整棵任务树空闲时进行，且不能有活动或后台 Shell、活动子任务或待审批；不满足条件返回 409，界面保留原方式并显示错误。子 Agent 继承根会话方式，不能独立切换。已签发许可绑定执行方式，命令记忆也包含执行方式，不能将沙箱批准复用成宿主批准。

sandbox 模式的 Shell 默认离线；单次联网是独立能力，仍保留文件隔离。隔离启动失败返回错误，不重试为普通进程。

批准命令只允许其启动，不扩大沙箱可访问的目录。审批卡列出当前可读、可写目录。命令失败且输出显示系统拒绝时，结果附带 `sandbox_denial` 和说明，Web 工具卡可一键为本会话只读授权目录；该判断来自输出文本，只作提示，不改变命令结果或授权。

host 模式使用真正的宿主 Shell，以运行 Wright 的账户权限执行，无系统文件或网络隔离，程序和子进程可以访问该账户能访问的宿主资源。审批策略照常生效：选择 host 不会自动选择 bypass；Plan/Ask 仍禁止 Shell。文件、HTTP 工具继续使用原授权入口和边界，但这些工具的授权不能限制宿主 Shell 内部的文件和网络行为。宿主审批显示该范围，不提供沙箱单次联网勾选，也不因沙箱组件不可用而禁止批准。

* Linux：系统安装的 Bubblewrap，私有 PID、IPC、UTS、用户和离线网络命名空间，最小挂载视图、只读运行时、私有临时目录。离线 seccomp 同时阻止新 socket 和 io_uring，避免已挂载 Unix socket 绕过网络隔离。需要允许用户命名空间及 seccomp 的内核配置。
* macOS 12+：系统 `/usr/bin/sandbox-exec`，按许可生成 Seatbelt 文件和网络规则；可用性通过真实探针检查。
* Windows 11：`wright --sandbox-setup` 或权限页请求管理员初始化两个独立低权限账户、系统 WFP 离线网络规则、只读运行时 ACL 和 DPAPI 凭据。每次执行使用限制 SID、临时资源 ACL、原生 PowerShell 和禁止子进程逃逸的 Job Object。ACL 和账户修改记录归属，清理仅撤销自身 SID；存在活动命令时不能删除网络隔离。`--sandbox-status` 查看状态；`--sandbox-cleanup` 清理。失败时聊天和文件工具仍可用，Shell 拒绝执行。

管理员初始化和网络规则属于一次设置。日常执行不更改系统目录 ACL，不请求管理员权限。无法取得资源能力 ACL 时执行失败，不扩大到整个用户目录。

## 验收与支持声明

`.github/workflows/ci.yml` 的 native-sandbox 矩阵在 Linux、macOS、Windows 上运行真实进程；Windows job 明确完成管理员初始化及最终清理。启用 `WRIGHT_SANDBOX_INTEGRATION=1` 后，任何缺失的依赖或隔离能力都会导致验收失败，不跳过测试。Windows 以 junction 验证路径绕过；普通账户的符号链接限制只影响对应符号链接用例。

当前实现不能仅凭单元测试声明三平台 Shell 支持完成。必须看到三平台原生隔离 CI 全部通过，才能改变支持状态。本地 Linux WSL 已通过真实隔离验收；当前本地 Windows 尚未初始化隔离账户，macOS 无本地验收环境，Windows 与 macOS 验收仍待对应 CI 完成。
